# Week 1 Summary: Event-Driven Programming

## 1. Key definitions

- **Event:** An action or occurrence detected by a program, such as a button click.
- **Event source:** The component that generates an event, such as a button, keyboard or sensor.
- **Event listener:** An object that waits for and receives events.
- **Event handler:** The code that executes in response to an event.
- **Event queue:** A structure that holds pending events until they are processed.
- **Event loop:** The process that checks the event queue and dispatches events for handling.
- **EDT:** The Java Swing Event Dispatch Thread, which processes Swing events and GUI updates.

## 2. Important diagrams

### EDP component relationship

```text
Event Source -> Event -> Listener -> Handler -> Application Response
```

### Event processing flow

```text
User / System Action
        |
        v
   Event Source
        |
        v
    Event Queue
        |
        v
     Event Loop
        |
        v
 Listener and Handler
        |
        v
     GUI Update
```

## 3. Programming paradigms

**Procedural programming** executes instructions in a planned sequence. It is useful for tasks with a clear beginning-to-end process.

**Event-driven programming** responds to events generated by users or the system. It is useful for graphical user interfaces and interactive applications.

## 4. Java Swing examples

A button can listen for clicks using an ActionListener:

```java
JButton button = new JButton("Click Me");

button.addActionListener(e -> {
    System.out.println("Button clicked!");
});
```

A Swing application should be started on the EDT:

```java
SwingUtilities.invokeLater(() -> {
    new MyWindow().setVisible(true);
});
```

Long-running tasks should not block the EDT. Background work can run on another thread, while Swing components are updated on the EDT using `SwingUtilities.invokeLater()`.

## 5. Important lessons

1. Event sources generate events.
2. Listeners receive events and invoke the appropriate handler code.
3. The event queue holds events waiting to be processed.
4. The event loop dispatches pending events.
5. Blocking the EDT can make a GUI freeze.
6. Swing components should be updated on the EDT.
7. Event-driven programming gives users more freedom to interact with an application.
